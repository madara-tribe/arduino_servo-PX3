Camera & Servo パラメータ
───────────────────────────────
	1.	パラメータ概要と意味
───────────────────────────────

[camera]
	•	解像度(W×H)：960×540 (1080p)
　→ トラッキング対象が適正サイズで映るよう調整。FOV71.91°を前提に角度計算精度を確保。
	•	FPS：30
　→ iPhone/Insta360 実測トラッキング環境に合わせた設定。30fpsでブラーと処理負荷のバランスが良好。

[サーボ側(Arduino + Python)]
	•	ボーレート：9600bps
　→ SG5010 + UNO 組み合わせで最も安定。115200bpsでは通信エラー発生があったため固定。
	•	信号範囲：500–2500µs
　→ SG5010 が安定して動作する範囲。0〜180°を線形マップ。
	•	受信形式：小数角 (例: “90.5\n”)
　→ float値を受け取り writeMicroseconds() に直接変換。
	•	INVERT_INPUT：Arduino側では使用しない（反転なし）
　→ 反転処理はPython側で行う。
	•	Python側設定：
　・BAUD_RATE = 9600
　・INVERT_ANGLE = True（反転処理）
　・deadband_deg = 2.0°（2°未満は送信抑制）
　・送信形式：”%.1f\n”（小数角送信）

───────────────────────────────
2. 実施したテスト内容
───────────────────────────────

[Test1: カメラ FPS / ブラーテスト]
　使用スクリプト：test2_camera_fps_exposure.py
　露光1/120, 1/250, 1/500条件でFPSとブラー指標を測定。
　→ FPS安定性とモーションブラー耐性の評価。

[Test2: サーボ微小ステップテスト]
　±0.5°, ±1°, ±2°の往復動作をGUIで実施。
　→ サーボの静止摩擦・応答限界を評価。

[Test3: 左右対称動作テスト]
　「90→90+Δ→90」「90→90−Δ→90」（Δ=1°, 2°）を個別実行。
　→ バックラッシュ・左右反応差の有無を確認。

───────────────────────────────
3. テスト結果と決定理由
───────────────────────────────

[カメラ]
	•	実測FPS：30fpsで常時安定。
	•	高速動作時もブラー指標は60%以上維持（相対比≥0.6）。
	•	露光1/120条件で明るさ・滑らかさのバランス最適。
→ 結論：30fps / 960×540 が最適。

[サーボ微小ステップ]
	•	±0.5°：不安定（2回に1回程度動作）
	•	±1°：2/3回動作。中心復帰時に遅れあり。
	•	±2°：常に安定・確実に動作。
→ 静止摩擦によるデッドゾーン ≈1.5〜2.0°。
→ 結論：deadband_deg=2.0° が最適。

[左右対称テスト]
	•	Δ=1°：左方向の動作がやや鈍い。
	•	Δ=2°：左右とも安定し対称。
→ 現状補正不要。中心±2°以上で安定追従。

4. 最終パラメータ
───────────────────────────────

カメラ
30fps / 960×540 / HFOV= 53.1°, DFOV 64
FOVはカメラの固有値


サーボ通信
9600bps / float角度 / 反転なし
UNO+SG5010で安定。115200bpsでは稀に通信ロス。

Python側反転
INVERT_ANGLE=True
Arduino側で反転すると二重反転となるためPC側で統一。
　　
deadband
±2°


───────────────────────────────
5. 今後の懸念・改善ポイント
───────────────────────────────
	•	電源安定性：SG5010は電流が大きく、USB給電では不足。外部5V電源＋GND共通を推奨。
	•	左右差：左方向がわずかに遅い。必要に応じてPython側で方向別補正(+0.3°)を検討。
	•	カメラFOV：960×540は非16:9。将来的に960×540へ変更し角度換算の誤差を減らす。
	•	温度・電圧変動：サーボ位置が変化する可能性あり。定期センタリングを検討。
